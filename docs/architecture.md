# Архітектура Second Brain

## Огляд

Локальний персональний Second Brain для студента — вебзастосунок для створення,
редагування та перегляду Markdown-нотаток, організованих за методологією PARA.

- **Один користувач**, авторизація не потрібна.
- Сервер слухає лише `127.0.0.1:5000`.
- Без зовнішніх API, без баз даних — файли `.md` є джерелом істини.

## Стек технологій

| Компонент | Технологія |
|---|---|
| Бекенд | Python 3.11+, Flask |
| Шаблони | Jinja2 |
| Парсинг нотаток | python-frontmatter, markdown |
| Тести | pytest |
| Сховище | Файли `.md` з YAML frontmatter |
| Версіонування | Git |

## Компоненти

### 1. Модуль даних (`src/notes.py`)

Відповідає за роботу з файлами нотаток. Не залежить від Flask.

- `load_all_notes()` — завантаження всіх `.md` із `notes/*/`
- `search(query)` — регістронезалежний пошук підрядка в title, tags, body
- `filter_by(tag, category)` — фільтрація за тегом та/або категорією
- `find_note_by_title(title)` — пошук нотатки за title (для резолвінгу `[[…]]`)
- `resolve_links(text)` — перетворення `[[Назва]]` на HTML-посилання
- `get_backlinks(title)` — список нотаток, що посилаються на дану
- `save_note(...)` — збереження нотатки (створення або оновлення); оновлює поле `updated`

### 2. Вебзастосунок (`src/app.py`)

Flask-маршрути:

| Маршрут | Метод | Опис |
|---|---|---|
| `/` | GET | Головна сторінка: список нотаток, бічна панель (категорії, теги), поле пошуку |
| `/note/<path>` | GET | Перегляд нотатки: рендер Markdown, посилання `[[…]]`, backlinks |
| `/new` | GET/POST | Форма створення нотатки (за замовчуванням — Inbox) |
| `/edit/<path>` | GET/POST | Форма редагування нотатки |

### 3. Шаблони (`src/templates/`)

- `base.html` — базовий шаблон з навігацією
- `index.html` — список нотаток з пошуком і фільтрами
- `note.html` — перегляд однієї нотатки
- `edit.html` — форма створення/редагування

### 4. Статичні файли (`src/static/`)

- `style.css` — стилі інтерфейсу

## Потоки даних

```
Браузер ←→ Flask (app.py) → notes.py → Файлова система (notes/*/*.md)
```

- Нотатки читаються з диска **при кожному запиті** (без кешу).
- Зміни зберігаються безпосередньо у `.md` файли.
- Після перезапуску сервера всі дані на місці.

## Модель нотатки

```yaml
---
title: "Назва нотатки"
created: "2026-10-23T11:00:00+03:00"
updated: "2026-10-23T11:00:00+03:00"
type: note          # note | moc
status: active      # inbox | active | archived
tags:
  - тег1
  - тег2
source: "власний конспект"
---

Тіло нотатки у **Markdown**.
Посилання: [[Інша нотатка]]
```

| Поле | Тип | Обов'язкове | Опис |
|---|---|---|---|
| `title` | string | ✅ | Унікальна назва нотатки |
| `created` | ISO 8601 | ✅ | Дата створення |
| `updated` | ISO 8601 | ✅ | Дата останнього оновлення |
| `type` | enum | ✅ | `note` або `moc` |
| `status` | enum | ✅ | `inbox` / `active` / `archived` |
| `tags` | list[str] | ❌ | Теги для фільтрації |
| `source` | string | ❌ | Джерело інформації |

**Категорія** визначається підпапкою (`notes/Inbox/`, `notes/Projects/` тощо).

## Критерії приймання

1. Головна сторінка показує всі нотатки з усіх категорій.
2. Бічна панель із категоріями та тегами; клік фільтрує список.
3. Пошук регістронезалежний по title, tags, body.
4. Порожній результат пошуку → повідомлення «Нічого не знайдено».
5. Сторінка нотатки рендерить Markdown у HTML.
6. `[[Назва]]` → клікабельне гіперпосилання.
7. Бите посилання `[[Неіснуюча]]` — червоне.
8. Блок «Посилаються сюди» (backlinks).
9. Створення нотатки → файл з'являється у `notes/Inbox/`.
10. Редагування → оновлює `updated`, зберігає на диск.
11. Після перезапуску сервера всі дані збережені.
12. Видалення через UI відсутнє.
13. Сервер слухає лише `127.0.0.1`.
14. Тести pytest проходять на тимчасових даних.

## Ризики

| Ризик | Мітигація |
|---|---|
| Випадковий коміт персональних даних | `.gitignore`; перевіряти `git diff` перед `push` |
| Пошкодження/видалення файлів | Git як версіонування; відсутність кнопки «Видалити» |
| Доступ з мережі | Хардкод `host="127.0.0.1"` |
| Кодування кирилиці у назвах | UTF-8 всюди; тестувати на Windows |
| XSS через вміст нотатки | Jinja2 автоекранування |
| Втрата даних при збої диска | Git remote як резервна копія |
